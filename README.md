**Instagram Downloader Chrome Extension**

instagram-downloader — это расширение для Chrome, которое позволяет скачивать фотографии и видео из Instagram.

**Функции:**
- Скачивание фото из постов Instagram
- Скачивание видео из постов Instagram
- Скачивание рилсов и историй
- Работает полностью в браузере, без сторонних сервисов


**Установка:**
1. Склонируйте репозиторий:
   git clone https://github.com/IvanYakunkin/instagram-downloader.git
2. Откройте Chrome и перейдите в chrome://extensions/
3. Включите "Режим разработчика"
4. Нажмите "Загрузить распакованное расширение" и выберите папку проекта dist после сборки
5. Расширение готово к использованию!

**Как работает:**  

Чтобы обнаружить посты на странице и добавить кнопки скачивания используется MutationObserver для получения контейнера с содержимым страницы и MutationObserver для детекта самих постов, которые подгружаются динамически. 

Instagram хранит адреса изображений в исходном виде, поэтому их скачивание не вызывает трудностей. С видео всё обстоит сложнее, так как в качестве src выступает blob-url и доступа к ссылке на видео по умолчанию нет. 

Instagram хранит каждое видео в нескольких видах: 
1) Полное видео
2) Видео без аудио
3) Аудио без видео

Для отображения на странице используется загрузка отдельного аудио и видео по сегментам. К полному же видео прямого доступа нет.

Instagram для отображения видео изначально выполняет множество XHR/fetch запросов, в ответе некоторых из них приходят media_id ресурса (pk), адрес исходгого видео, ссылки на видеоряд/аудио, информация о сегментировании и
множество других данных.  

Для возпроизведения видео создается MediaSource и уникальная ссылка через URL.createObjectURL(MediaSource). Затем выполняются fetch-запросы для получения blob-сегментов видео и аудио по отдельности, которые переводятся в ArrayBuffer. 
Далее эти ArrayBuffer-сегменты добавляются в MediaSource через appendBuffer(). По итогу blob-ссылка указывает не на само видео, а на MediaSource, который его воспроизводит, и получить видео по ней невозможно.  

Однако, существует несколько способов получить исходное видео:
1) Инжектить скрипт до полной прогрузки страницы, который будет изменять некоторые встроенные методы, и находить связь blob-адреса к адресам аудио и видео файлов;
2) Перехватывать XHR/fetch запросы для получения media_id видео, затем каким-либо способом сохранять его. В момент скачивания видео делать GET-запрос на /api/v1/media/{media_id}/info/. Ответ будет содержать
адрес исходного видео со звуком.

В расширении на данный момент реализован только первый метод. Перехватываются и модифицируются window.fetch(), new MediaSource(), URL.createObjectURL() и формируется объект со связью blob-ссылки к ссылкам на аудио и видео по отдельности. 

**Примечание:** Изначально ссылка указывает на сегмент видео/аудио через параметры url &bytestart и &byteend, однако, если сделать запрос без них, можно будет получить доступ на полное видео или аудио.

Таким образом, происходит загрузка видео и аудио файлов по отдельности. Из браузера по умолчанию склеить эти файлы не получится.
Поэтому можно либо установить ffmpeg.wasm и использовать его из браузера, либо отправлять на отдельный сервер video_url и audio_url, там делать запросы и склеивать файлы через ffmpeg. Всё это снижает скорость скачивания видео, поэтому
в планах сделать второй способ загрузки видео без необходимости склейки.
